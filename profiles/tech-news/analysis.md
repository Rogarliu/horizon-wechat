# 评估目标

判断一条内容对「科技辉说」的读者有多值得读。

读者画像：对科技和 AI 有兴趣，但**不是从业者**。他们关心「发生了什么」「跟我有什么关系」
「这事有意思在哪」，不关心论文细节、架构取舍和代码实现。

# 评分标准

- **9-10：今天必须知道。** 头部公司的重大发布、行业格局变化、影响大量普通用户的产品更新、被广泛讨论的事件。
- **7-8：值得一读。** 有明确新闻点，普通人能看懂，读完能跟人聊两句。包括有话题性的产品、有趣的实验、行业人事与商业动向、被广泛传播的观点。
- **5-6：知道也行，但不着急。** 垂直领域进展、需要一点背景知识才能理解的技术新闻。
- **3-4：门槛偏高。** 需要专业背景才能读懂的技术细节、实现原理、性能调优、学术论文、工程实践复盘。
- **0-2：噪音。** 纯推广、招聘、例行更新、无信息量的转载。

# 打分原则

1. **可读性优先于技术含量。** 需要计算机专业背景才能理解的内容，即使技术很硬，也不该给到 7 分以上。
2. **有具体事件优先于泛泛而谈。**「某公司发布了 X」优于「关于 X 的思考」。
3. **跟普通人有关的加分。** 涉及产品价格、隐私、就业、日常使用的，往高分走。
4. **趣味性是加分项。** 反常识的发现、有趣的实验、意外的结果，值得给高分。
5. **不要被标题党骗。** 标题夸张但内容空洞的，压低分数。
6. **纯学术论文、benchmark 刷榜、框架内部实现、源码分析，一律 4 分以下**——除非它已经变成大众话题。
7. **合规红线：涉及未成年人受侵害、性犯罪、血腥暴力、政治敏感的题材，一律 3 分以下。**
   这类内容新闻价值再高也不选——公众号审核会拦，轻则删文重则封号。
   宁可少一条，不要冒这个险。
8. **时效性：讲的是旧事就不算新闻。** 判断依据是**内容主体事件发生的时间**，
   不是文章发布的时间。如果主体事件发生在 3 天以前（常见于
   「XX 全知道」「All the news about X」「盘点」「回顾」这类聚合页，
   它们的时间戳会随每次更新刷新，看起来像新发的），一律压到 3 分以下。
   判断方法：看摘要和正文里提到的时间点，以及事件是「刚刚发生」还是「此前已发生」。

# 输出要求

- **summary：必须用简体中文写**，2-3 句，说清「发生了什么 + 为什么值得关注」，不超过 90 字。
  不要写「本文介绍了」「文章讨论了」这类废话，直接讲事情。
- **tags：3-5 个具体标签**，用中文或通用英文术语（如 OpenAI、芯片、隐私）。
